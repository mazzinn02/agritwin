## Executive Summary

The database migration from Firebase to **Supabase (PostgreSQL)** has been fully executed, verified, and pushed to GitHub. All telemetry observations generated by edge devices and the 12-second simulator now stream directly into Supabase PostgreSQL, with real-time WebSockets updating the live UI. Firebase remains active as an automatic secondary fallback mechanism.

## 1. Tables Created

The following SQL migration was generated at `supabase/migrations/001_initial_schema.sql` and `supabase_schema.sql`:

1. **`telemetry_observations`**
   - **Columns**: `id` (PK, TEXT), `farm_id`, `plot_id`, `device_id`, `sensor_id`, `parameter_key`, `display_name`, `value` (NUMERIC), `unit`, `measurement_timestamp` (TIMESTAMPTZ), `received_timestamp` (TIMESTAMPTZ), `quality_status`, `data_source`, `notes`, `metadata` (JSONB).
2. **`farms`**
   - **Columns**: `id` (PK, TEXT), `name`, `location`, `total_area` (NUMERIC), `unit`, `sections_count` (INTEGER).
3. **`plots`**
   - **Columns**: `id` (PK, TEXT), `farm_id`, `code`, `name`, `area`, `area_unit`, `crop_id`, `sensor_node_id`, `soil_moisture`, `air_temp`, `soil_ph`, `days_planted`.

## 4. Fallback Mechanism

- **Primary**: Supabase PostgreSQL DB.
- **Secondary (Fallback)**: Firebase Firestore.
- **Behavior**: If a Supabase write fails, the system automatically falls back to Firebase and logs:
  ```text
  [SUPABASE FAILED]
  [FIREBASE FALLBACK ACTIVE]
  ```
